Fix Copybuffer’s Linux remote-terminal clipboard handling and false-success behavior.

Observed bug in Copybuffer 1.10.0:

* The session had `DISPLAY=localhost:12.0`, but the X11 display was unusable because no authorization cookie was available.
* Copybuffer treated the presence of `DISPLAY` as proof that X11 worked.
* `pyperclip.copy()` selected `xclip`.
* `xclip` printed `Error: Can't open display: localhost:12.0` and failed.
* Copybuffer still printed `STDIN copied to the clipboard successfully!` and exited with status `0`.
* Operating System Command 52 (OSC 52) worked correctly in the same terminal session.

Reproduction:

```bash
export DISPLAY=localhost:12.0
printf 'test' | cb
echo "$?"
```

Current incorrect result:

* `xclip` reports that it cannot open the display.
* `cb` prints a success message.
* Exit status is `0`.
* The clipboard is unchanged.

Implement the following:

1. Correct failure propagation
2. Add an OSC 52 text clipboard backend
3. Make backend selection explicit and testable
4. Improve automatic backend behavior
5. Preserve existing functionality
6. Add automated tests
7. Documentation
